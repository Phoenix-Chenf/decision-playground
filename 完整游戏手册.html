怎么组织一局

单人

先读公开情境与角色开场，再做操作。尽量保留初始判断，之后揭示变化和参考路径。可以只阅读，但应记录“尚未实际尝试”。单人不能实现真正私有信息隔离。

多人

主持人分别发角色私有卡；确定谁扮演负责人，谁是参与人。先约定目的、边界、记录与停止方式。角色可依据自己的上下文拒绝承诺，但不必为了戏剧效果制造对抗。

外部 AI

同目录“主持提示词”文件夹包含 60 份完整提示。由你自行复制，不存在页面自动联网或实时模型。主持人应逐轮回应，保留角色约束，允许不同合理路径。

每局五步

  1. 情境：明确本次选择、授权和已有事实。
  2. 操作：记录安排与依据，不急着揭示答案。
  3. 变化：只重谈受新信息影响的承诺。
  4. 复盘：区分事实、推断、未知与反证。
  5. 归档：留下下一次观察或停止的选择。

共同边界

  • 不预设真实组织会议没有执行；本套练习用于表达决定与变化。
  • 不将真实同事作为未经同意的心理分析对象。
  • 不把模拟表现升级成真实业务、效能或市场证据。
  • 导出的个人记录需要自行脱敏，游戏材料本身不含内部人员与经营事实。
组合 / 保存 / 迁移

按兴趣走，不按进度赶

先理解，再握手

A1 → C2 → C4 → A6
从隐藏上下文到可执行承诺。四局之间可以复用同一份虚构场景。

把经验变成方法

A4 → B1 → B4 → D3
从依赖、证据与工作流中，提炼能够离开原组织使用的方法。

未来工作的试住

D1 → D2 → D4 → B5
体验任务、移除内部身份、回答合作方质疑，最后检查服务成本。

不赶路的好奇心

C1 → C3 → D5 → D6
理解一种表达，检验一种解释，观察一次体验，尝试一种兴趣。

四种组合导向

  • 职业积累：A＋B，连接讨论过程与证据判断。
  • 心理学、谈判与引导：A＋C，理解上下文并形成选择。
  • 未来选择权：B＋D，检验方法与服务离开原组织后的条件。
  • 轻负担好奇：C＋D，允许只有体验、不形成职业成果。

把记录带走

HTML 优先使用浏览器本地存储，无法保存时会提示。迁移前导出 JSON，新环境导入按更新时间合并。每局只保留一个当前活动版本；重新开始前导出上一局。Markdown 用于长期阅读，打印用于纸上记录。

完整手册中的参考路径不是唯一标准答案。计算模型可检查明示约束，不替负责人取舍；完成游戏不等于完成真实试点。

A1 / 组织决策实验室 / 情境与角色

上下文拼图

没有争吵，也可能没有同一幅地图 · 35 分钟 · 1-5 人 · 入门

发生了什么

一家虚构的生活服务产品准备规划下一季度。业务、产品、研发和平台各自有清晰计划，却还没有在公开场合握手。负责人希望大家提出可承接的共同安排，并未要求先解决某个冲突。你主持第一次共创会，手里只有各方开场发言。目标不是快速统一口号，而是让各方知道彼此为什么这样安排。

用最多四次信息揭示，形成一张事实、目标、约束、待确认事项的共同地图。

角色卡 · 主持人掌握，按需分别发放

业务负责人

开场：“我们要让新用户更快完成第一件事。”
私有上下文：业务看到新用户在前两步退出，但现有统计只能显示退出位置，不能证明退出原因。
希望：先验证最影响首次完成的环节。
边界：没有证据前不把问题归因给某个团队。

产品负责人

开场：“我准备补三个关键场景。”
私有上下文：三场景来自一组访谈，样本偏向高频用户；两个场景共享同一能力，第三个依赖尚未准备好。
希望：保留已发现的需求，同时确认先后顺序。
边界：不承诺三场景同时上线。

研发负责人

开场：“我们需要先明确哪些不做。”
私有上下文：最近有两个必须兑现的外部交付，占用下一周期约一半容量；不是拒绝新需求。
希望：让已有承诺和新任务一起进入讨论。
边界：不能把已承诺资源当成空闲资源。

平台负责人

开场：“先看公共能力能不能复用。”
私有上下文：已有检索组件能覆盖两个场景，但需要补一项授权和一个验收样例；目前没有共同维护约定。
希望：让复用决定和维护责任同时被确认。
边界：能调用不等于已经可靠可用。

桌面材料

议程邀请：讨论目标：共同安排下季度第一阶段，不要求当场锁定全年细节。

开场白：四位负责人均表示支持业务目标，但使用了不同的范围、时间和证据口径。

空白地图：四个区域：已知事实 / 各方目标 / 约束与承诺 / 还需确认。不要把推断写入事实区。

三轮安排：1. 先写你的开场问题，再选择要公开的上下文。 2. 每揭示一张卡，更新共同地图；不要只摘抄发言。 3. 说明哪些决定现在可做，哪些需要新的证据或负责人授权。

A1 / 上下文拼图 / 操作、变化与复盘

独立操作机制

先记录开场与共同地图，再逐次揭示信息。每揭示一次就说明它改变了什么；预算用完后，把剩余未知交给具体确认人。多人由主持人分别发私有卡，单人靠自觉不提前看完整上下文。

业务：为什么是首次完成？：退出位置可见，退出原因未被验证。先保留竞争解释。

产品：三个场景从哪里来？：访谈样本偏高频，两场景共用能力，一场景依赖未就绪。

研发：哪些资源已经承诺？：一半容量已有外部交付承诺。计划应使用剩余容量。

平台：复用还差什么？：补授权、样例与维护责任之后才能判定可复用。

变化事件 · 一个新事实

负责人补充：预算没有变化，但第一阶段必须只选一条能获得反馈的完整路径。请标明这改变了哪一项安排，而不是让所有人重新写计划。

参考路径与反例

  • 可行开场：请各位各说一项已知事实、一项必须守住的承诺，以及一项希望本次决定的事。
  • 一种收敛方式：先选两个可复用场景中的一个，确认首次完成的观察口径；不把另一场景判定为无价值。
  • 反例：直接宣布研发先支持三场景，再请平台兜底。这替参与人作了承诺。

复盘问题

  1. 哪条信息真正改变了你的安排？
  2. 你是否把别人表达的目标误写成事实？
  3. 哪些信息只能由本人公开，不能靠主持人代替解释？
  4. 若缺少内部身份，你如何获得公开上下文的许可？

可迁移方法

  • 先对齐上下文，不以冲突作为会议成立的前提。
  • 把已有承诺摆上桌，才能谈新增承诺。
  • 共同地图的价值在于支持下一步选择，不在于写得全面。

容易走偏

  • 过早问“大家同不同意”，只得到表面一致。
  • 将容量约束解释为态度问题，或用业务口号覆盖产品证据。

本局交付

一张四区共同地图；一个第一阶段可讨论的范围；一份待确认问题及确认人名单。

迁移边界：适合尚未公开对齐的计划讨论。单人翻卡能练结构，但不能证明你能在真实团队中建立信任。

A2 / 组织决策实验室 / 情境与角色

TOP3 收敛

取舍由谁作出，比口号是否一致更重要 · 40 分钟 · 1-6 人 · 中阶

发生了什么

虚构业务下一季度有六个值得推进的目标，全部都有人支持。负责人最多选择三个重点，并且愿意说明为什么。你需要让讨论同时看到用户价值、证据成熟度和投入，而不是把支持人数最多的目标当成自然胜者。资源暂以容量点表达，不代表真实人力估算；这轮可用容量为十点。

提出不超过三个、合计不超过十点的目标组合，并把建议与负责人决定分开。

角色卡 · 主持人掌握，按需分别发放

负责人

开场：“我拍前三重点，也负责说明放弃什么。”
私有上下文：关注近期价值，也保留战略能力，但不要求每个领域都拥有一个重点。
希望：看到不同组合及后果。
边界：参与人投票是输入，不自动替代本人决定。

领域负责人

开场：“我需要知道为什么我的目标没有入选。”
私有上下文：落选目标可能是延期、维持或停止，三者不能混写。
希望：明确未入选项目的处理方式。
边界：不接受“以后再说”作为资源安排。

桌面材料

容量点：十点只用于演练取舍。每个目标的点数是设计假设，不是审计过的人月。

选择权：引导师组织比较；负责人选 TOP3；领域负责人决定可承担的实现方式。

组合原则：看组合是否支持共同方向，而非机械平分给各部门。

三轮安排：1. 选择一个初始组合，记录为什么不选其他目标。 2. 把至少一个替代组合摆上桌，比较风险和延后代价。 3. 记录负责人决定、承接范围，以及未入选项目的处理。

A2 / TOP3 收敛 / 操作、变化与复盘

独立操作机制

勾选最多三个目标，容量按明示点数相加。初始十点，事件后八点；超限意味着需要重谈范围或组合，不是能力失败。至少比较两套组合，负责人拍 TOP3，参与人选择承接方式。

提升核心任务完成 / 4 点：用户证据较充分；能形成第一阶段反馈。

关键链路稳定性 / 3 点：近期故障已定位；价值体现为减少失败，不是新增功能。

单位服务成本 / 3 点：基线明确，但不能以牺牲质量换低价。

扩展场景覆盖 / 5 点：需求存在；部分依赖未准备好。

公共能力复用 / 4 点：战略价值可能较高；近期收益需要与具体场景绑定。

新入口实验 / 2 点：低投入可实验；规模结果不等于留存。

变化事件 · 新约束到来

已承诺交付多占两点容量，当前可用容量由十点降为八点。保留原决定的理由，但重新说明哪些承诺需要调整。

参考路径与反例

  • 一种可行组合：任务完成四点、稳定性三点、新入口实验两点，合计九点。它不自动优于其他组合。
  • 容量降至八点后，可以缩小入口实验，也可以换组合；必须由相关方确认缩小是否仍能产生有效反馈。
  • 反例：先挑最响亮的三个目标，再要求各团队自己挤出资源。

复盘问题

  1. 是否先谈共同方向，再谈目标数量？
  2. 有没有把“每人分一个”当作公平？
  3. 谁决定优先级，谁决定实现方式？
  4. 新约束改变的是目标、范围还是节奏？

可迁移方法

  • 容量约束公开，但不将粗估当成精确测量。
  • 保留替代方案，让拍板不是一次盲选。
  • 落选项目也需要明确状态。

容易走偏

  • 通过人为打分制造唯一正确答案。
  • 把负责人选择写成主持人决定，或让参与人承诺未知资源。

本局交付

两个可比较组合；负责人 TOP3 决定与取舍理由；未入选目标的维持、延期或停止安排。

迁移边界：适合战略收敛与阶段规划。这里的点数只是演练模型，真实资源决策需要核验容量、依赖与责任。

A3 / 组织决策实验室 / 情境与角色

年度目标倒推

从未来状态，走回第一个可验证节点 · 45 分钟 · 1-5 人 · 中阶

发生了什么

虚构智能服务希望一年后能稳定完成一种复杂任务。负责人已确认方向，但还未规定如何实现。团队提出调研、评测、能力建设、试点和扩展等工作。你需要协助参与人把未来状态变成有先后依赖的路径，允许学习后调整，而不是把一年拆成十二份工作量相同的任务清单。

安排六项工作所在季度，识别先后依赖，并为第一阶段留下一个可验证结果。

角色卡 · 主持人掌握，按需分别发放

业务负责人

开场：“一年后应能解决完整任务，不是功能数量增长。”
私有上下文：允许调整路线，但每阶段需要看得懂的结果。
希望：方向清晰、反馈及时。
边界：不要求现在预测全部细节。

产品与研发负责人

开场：“需要区分学习任务和兑现承诺。”
私有上下文：评测口径与需求边界共同影响试点；规模化在关键链路验证之后。

边界：本局模型是公开约束，不是对现实人力的估算。
